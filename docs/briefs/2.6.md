## Approved design

- **Recording.** A new command, `fid usage record --hold <id> --actor
  <actor> --format codex|claude --input <file> --idempotency-key <key>`
  (operation `usage.record`). `--hold` takes the hold or review claim ID
  that `next --claim` returned for the session. The actor must be the one
  that hold or claim names; it needn't still be current, because an agent's
  own waiting park ends its hold before the loop records. fid reads the
  file, finds the usage and appends one Event with:
  - the task, the hold or claim, the actor and the hold's model;
  - the session's role (build, fix, or review with its stream), which fid
    derives from the hold or claim and the caller never asserts;
  - the format, the counts by category (and by model where the output
    reports models), the headline total, and the input's sha256 digest.

  Recording the same output (digest) twice for the same hold or claim is
  refused, so a session can't be counted twice; an idempotent retry returns
  the first result. An unknown format, malformed output or output with no
  usage is refused with a clear error and no Event (use the CLI's error
  registry for the codes).
- **Formats.** Use the real samples at the end of this brief as test
  fixtures.
  - `codex` is `codex exec --json` stdout (JSONL). Sum the `usage` of every
    `turn.completed` event and ignore the other event types. Its fields:
    `input_tokens` (which includes cached input), `cached_input_tokens`,
    `cache_write_input_tokens`, `output_tokens` and
    `reasoning_output_tokens`. Codex reports no model, so use the hold's.
  - `claude` is `claude -p --output-format json` (one object) or
    `--output-format stream-json --verbose` (JSONL, whose last line is the
    `result` object). Use `modelUsage` (per model: `inputTokens`,
    `outputTokens`, `cacheReadInputTokens`, `cacheCreationInputTokens`),
    falling back to `usage` when it is absent. Claude's input count excludes
    cache reads and writes.
  - Normalise to uncached input, cache read, cache write, output and
    reasoning (part of output, kept for information). The headline total is
    everything the model processed: uncached input + cache read + cache
    write + output. Keep the reported numbers too, so another total can be
    derived later.
- **Reporting.** `fid show <task>` gets a Usage line: the total, split by
  role and by model, and the number of sessions. Its JSON gains an optional
  `usage` object, absent or null when nothing is recorded. The projection
  gets a usage table (one row per recorded session) that `fid sql` can
  query, documented in `03_TRD_SCHEMA.md`. No new report command.
- **The loop.**
  - The default agent commands add `--json` (Codex). The agent's stdout and
    stderr go to separate files in the run directory, so usage is read from
    clean stdout.
  - After every agent session, whether it succeeded or failed, the loop
    runs `fid usage record` for that session, using a per-role format
    setting (`LOOP_BUILDER_USAGE` and `LOOP_REVIEWER_USAGE`: `codex` by
    default, `claude`, or `none`). For a review, record before
    `review record`; for a failed build, before the interruption park. A
    refused or failed usage record is printed and the loop carries on:
    usage is insight, not a gate. Every other fid call keeps the contract's
    loud failures.
  - Remove the 150-line limit: RESET.md's "The loop stays under 150 lines",
    `TestLoopLineBudget`, and D2's guard-rail "a line budget enforced by a
    test" (amend it in the decisions record, quoting Mark).
- **Contract.** Declare `usage record` in `LOOP_CONTRACT.md` (operation,
  exits, the result fields), with goldens. An added command is additive, so
  the version stays `fid-cli.v1`.
- **Config docs.** `04_TRD_CONFIG.md` and `.fid.toml`'s comment say
  `token_budget` is parsed and validated but not enforced until FID-fb8271.
  Don't change the parser or the policy snapshots.
