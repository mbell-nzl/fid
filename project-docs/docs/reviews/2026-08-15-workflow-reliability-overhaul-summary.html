Executive Summary

The recurring stoppages were primarily a routing defect, not weak engineering gates and not impatient process termination.

The workflow correctly noticed red tests, missing evidence, incomplete reports, and QA findings, but its binary RESUME | BLOCK model had no safe destination for real work that was local, in scope, and decision-free. The overhaul adds that missing destination: REPAIR.

Only four of the 31 formal stops needed direct Human input: Phase 17 model qualification, Phase 17 final Human verification, Phase 19 kickoff approval, and Phase 19 final Human verification. No implementation failure, gate failure, report defect, or incomplete task required Human judgment.

Strict evidence rules remain intact. A failed attempt stays failed, a silent process is never presumed complete, required commands remain exact, and QA findings remain open until independently re-reviewed. What changed is the action after a recoverable failure.

Task 10 answer

The Developer stopped itself after 616 seconds. Session evidence shows normal task_complete with no timeout, cancellation, kill, Phase Runner interrupt, or context-exhaustion event. The Phase Runner then accepted the child-authored blocker instead of classifying it.

What Was Broken

  • Binary triage: a real unresolved local defect could not honestly be RESUME, so it became BLOCK even when a Developer continuation could fix it.
  • Ambiguous session rule: “one task per Developer session” was read as “one Developer session per task,” making fresh same-task continuation look forbidden.
  • Child blocker authority: the Phase Runner treated a Developer’s “blocked” label as a lifecycle decision instead of an observation to classify.
  • QA severity conflation: a must-fix finding with clear task ownership still forced Human triage because severity and protected authority were not separated.
  • Report inference: completion, recovery, and protected blockage were inferred from prose, and PASS termination evidence was not mechanically enforced.
  • Silent command handling: prompt ambiguity around nested live sessions made several-minute race/integration runs look abandoned when they were still compiling or executing.

The New Task Lifecycle

Recovery loops without advancing the task. Only protected conditions or exhausted no-progress budgets enter BLOCKED.

Binding Dispositions

DispositionMeaningRequired action
RESUMEThe trigger is already cleared, misclassified, or resolved with verified evidence.Advance from the current checkpoint.
REPAIRThe trigger is real, local, inside existing authority, and decision-free.Do not advance. Record recovery, continue the same task, rerun exact verification, and repeat affected independent review.
BLOCKA protected decision, unsafe condition, unrepairable external dependency, contradictory contract, or exhausted recovery budget prevents progress.Record triage, allocate/reference an ESC, append STOP, and request the named authority or external action.

What Was Implemented

  • Typed report outcomes: COMPLETE | RECOVERY_REQUIRED | BLOCKED.
  • Closed recovery and protected-blocker category registries.
  • Deterministic workflow-route.sh action reduction.
  • Append-only RUN-RESUME, TASK-RECOVERY, and REPAIR ledger events.
  • Strict post-marker sequence validation before append, including task/review identity and QA recovery ordering.
  • Exact PASS parsing: final exact row, observed exit 0, prior FAIL retained, no substring matches such as “NOT PASS.”
  • Same-task continuation across any necessary number of Developer sessions.
  • Two consecutive no-progress continuation attempts before budget exhaustion triage.
  • QA outcomes PASS | REPAIR | BLOCK, explicit owner, and fresh independent re-review.
  • TL-Lite/full Tech Lead ownership of ESC allocation; QA and Developers emit candidates only.
  • Retain-and-poll rules for silent live command sessions and observed termination receipts.
  • Synchronized canonical, Claude, and Codex role prompts plus workflow lint guards against semantic drift.

Independent Review

The independent reviewer did not rubber-stamp the first implementation. It found several unsafe advancement paths; each was repaired and covered by negative drills before PASS.

PASS parsing hardened

Rejected nonzero “PASS,” substring matches, contradictory final rows, and accidental loss of prior FAIL evidence.

Legacy escalation removed

Continuation across multiple Developer sessions no longer becomes an escalation by itself.

Sequence bypasses closed

Missing task IDs, overlapping recovery identities, and QA completion without repair evidence now fail validation.

Pre-append validation

An invalid proposed entry cannot permanently wedge the append-only ledger.

Progress semantics tightened

Unrelated churn cannot reset the no-progress budget; progress must discharge or narrow the trigger.

V2 Adoption Guidance

V2 is directionally aligned, but not adoption-ready.

Its accepted target already describes scoped gate repair, linked-Run interruption recovery, and same-Issue review rework. Its current implementation still uses the superseded WorkItem model, production roles remain unavailable, and all twelve fid capabilities remain unqualified.

Adoption requirementWhy it matters
Resolve open-Stop versus repair authorityAn active Envelope with an open Stop currently forbids the Builder action needed to repair retryable gate-failed.
Richer recovery dispositionA Boolean retryable cannot express actor, transition, same-Run eligibility, Human attention, or budget.
Immutable Attempts and ReceiptsFailed and passing attempts must coexist, with exact registered gate identity and terminal evidence.
Real linked-Run recoveryRecovery needs executor-liveness proof and non-destructive repository reconciliation, not fixture-only semantics.
Independent review reworkMust-fix ownership, fresh re-review identity, and budget exhaustion need executable conformance scenarios.
Qualification workComplete V2-2 correction, twelve capability qualifications, V2-3 recovery evidence, V2-4 role/provider qualification, and V2-6 dogfood.

Do not port: V1’s Markdown report grammar, fixed headings, two-commit report ceremony, tool-specific session IDs, Phase Runner/TL-Lite roles, TRG/ESC routing, or manual stash mechanics. Port the semantics: immutable attempts, scoped repair, exact gates, terminal receipts, canonical-state recovery, independent finding resolution, and protected-only Human attention.

  • The silent-process drill exercises real OS process liveness and polling, but cannot reproduce every provider’s nested tool wrapper. Canonical prompts therefore remain part of the control.
  • The linked-worktree VCS-stamping defect remains a local Go/tooling quirk. Final evidence came from the exact committed tree in a normal clone, not from disabling VCS stamping.
  • This is a deliberate V1 process patch. The separate V2 starter kit still needs its adoption workstream; it was not edited during this recovery.
