What Actually Failed

Task 17 recorded a backslash-bearing command exactly as specified. report-lint.sh transported that text through awk -v, which interpreted the escape before comparison. The evidence and declaration were byte-identical, but the control falsely reported that they differed.

The existing workflow then had only two useful classifications: repair the original task or BLOCK a protected control change. Because Task 17 did not own the canonical parser, a uniquely determined implementation repair was incorrectly forced toward Human escalation.

What did not change

No command, expected exit, VAL assertion, product behavior, dependency, public interface, threshold, tolerance, review boundary, or Task 17 evidence token was weakened or replaced.

Decision Context

  • DEC-136 separated task scope from workflow protocol. Task specs must not override the canonical commit/report sequence, gate tokens must retain a meaningful command-output marker, and evidence is rerun and recaptured rather than reconstructed from memory.
  • DEC-138 allowed a same-session repair only for a stale bookkeeping inventory whose discrepancy is named and decision-free. It never authorized changing a test, verdict, threshold, or product assertion: “fix the bookkeeping, never the verdict.”
  • DEC-146 adds the missing category used here. If an accepted control contract uniquely determines behavior and only its implementation is defective, TL-Lite may authorize a bounded REPAIR / control-conformance. Any semantic ambiguity or proposed gate-definition change still BLOCKs.

What Was Implemented

1. DiagnosePreserve failed evidence and identify the accepted contract, exact mismatch, task identity, trigger, and recovery budget.
2. IsolateUse a clean temporary repair worktree. Permit only explicitly named project-docs/tools/ files and one repair commit.
3. VerifyExecute a verifier materialized from the trusted base, bind the exact ordered allowlist into its receipt, and fast-forward only after PASS.
4. ContinueReturn to a report-only same-task continuation, rerun the exact originating verification, complete the task, and obtain fresh QA re-review.
  • Byte-safe report parsing: literal backslashes and horizontal tabs are compared without awk escape normalization; normalized near misses still fail.
  • Transactional ledger append: validate candidate plus immutable history, append atomically at EOF, return a receipt, and reconcile a lost receipt idempotently.
  • Typed schema-v2 recovery: exact-one event fields, canonical headings, external TRG/decision authority, STOP/resume identity, monotonic attempts, and no silent task or trigger replacement.
  • Scope protection: canonical base/head IDs, one-commit ancestry, clean isolated worktree, no hidden index flags, no symlink/gitlink substitution, no control-byte allowlist injection, and no self-authorization by either verifier.
  • QA continuity: REPAIR cannot advance; the owning task must repair and a fresh linked review must close the finding.
