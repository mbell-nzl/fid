## Purpose

This file is the finite set of validation assertions that must be true when
Phase 19 is complete. The validation contract specifies **what must be
proven**; the QA plan (QA Lead) specifies **how to prove it**.

Phase 18 made workflow *structure* data. Phase 19 makes it *authorable*:
`fid workflow define` writes user workflows as journal events into the same
projected workflow tables, `fid workflow assign` binds a workflow to an issue
kind or to the project, `fid workflow list` reads them back in every supported
format, and the `escalation-default` workflow (PRD-WF-005a) is seeded as
system reference data.

If a required validation assertion cannot be satisfied, stop and escalate
instead of weakening the assertion or silently adapting the spec.

## Numbering

- IDs use `VAL-NNN`, scoped to Phase 19, sequential from `VAL-001`.
- Retired or superseded assertions stay in the table with status and
  rationale; IDs are not reused.

- Every `VAL-NNN` is owned by exactly one task or `phase-end` window and has
  exactly one validator role. VAL-026 is the only `Human` assertion and is
  explicitly marked for fan-out into per-observable checklist rows.
- Performance controls (TRD-PERF-001 read, TRD-PERF-003 rebuild) are proven
  by the Task 6 benchmark gate and recorded against the CF-024 headroom, not
  by a `VAL-NNN`; see Task 6 acceptance criteria.
- CF-021 (doc comments on `maintenance.VacuumResult` / `Vacuum`) is a Task 6
  acceptance criterion, not a validation assertion.
- Out of scope for Phase 19 (own assertions in later phases):
  `role_permissions` migration, `fid role create`, `fid policy set`, and
  configurable permissions for custom state names (Phase 20); the escalation
  **entity** CLI and the `activity_log` ref-type extension (v0.2d); any gate

  editing, or deletion commands (unscheduled).
