# TRD CONFIG — fid

> `.fid/` directory structure, configuration file formats, and
> gitignore policy. Extracted from `scaffold/initial-spec.md` §11.1
> and scattered references in the TRD and initial spec.

---

## 1. `.fid/` Directory Structure

`fid init` creates the `.fid/` directory at the project root with the
following layout:

```
.fid/
├── journal/
│   └── YYYY-MM-DD.jsonl       # append-only journal; one file per UTC day
├── config.toml                # project configuration
├── pricing.toml               # model pricing data
├── gates.toml                 # registered gate definitions (v0.2b)
├── artifacts/                 # content-addressed full gate logs (v0.2b, gitignored)
├── fid.sqlite                 # derived query cache (gitignored)
└── .gitignore                 # ignores fid.sqlite and artifacts/
```

| Path | Purpose | Committed to git? |
|---|---|---|
| `journal/YYYY-MM-DD.jsonl` | Source of truth. Append-only event journal. Filenames use the UTC date from the event writer's single clock read. | Yes |
| `config.toml` | Project-scoped configuration. | Yes |
| `pricing.toml` | Model pricing data (ships with defaults, user-overridable). | Yes |
| `gates.toml` (v0.2b) | Trusted gate registry: versioned gate definitions fid may execute (TRD-SEC-005). Changes are reviewed config changes. | Yes |
| `artifacts/` (v0.2b) | Content-addressed full stdout/stderr logs referenced by receipts (`log_artifact_ref`), kept under the `[gates]` retention policy. The journal keeps only excerpts and hashes (TRD-SEC-008). | No (gitignored) |
| `fid.sqlite` | SQLite query cache. Derived projection of the journal. Deletable and rebuilt via `fid rebuild`. | No (gitignored) |
| `.gitignore` | Contains `fid.sqlite` and `artifacts/` | Yes |

## 2. `config.toml`

Project-scoped configuration. Created by `fid init` with sensible
defaults.

```toml
# Project identity
[project]
prefix = "FID"                 # issue ID prefix; set at init

# Maintenance audit settings
[maintenance]
started_without_claim_grace_seconds = 300

# Export settings (v0.4)
[export]
markdown_root = "./docs/"      # output directory for fid export
layout = "whet"                # 'whet' | 'flat' | 'custom'
banner = true                  # emit "generated by fid" banner in exported files

# Future sections (not present in v0.4 config):
# [sync]                       # v0.5+: canonical = "db" | "md", auto_export = true | false
```

### 2.1 Sections

| Section | Version | Keys | Notes |
|---|---|---|---|
| `[project]` | v0.1 | `prefix` | Set at `fid init --prefix <PREFIX>`. Immutable after init. |
| `[maintenance]` | v0.1 | `started_without_claim_grace_seconds` | Grace before a started-category issue without a live claim becomes a maintenance warning. Default 300 seconds. |
| `[gates]` | v0.2b | `output_excerpt_max_bytes`, `artifact_retention_days`, `allow_shell_mode` | Execution capture bounds, full-log artifact retention, and the policy switch for the higher-risk shell-mode escape (default `false`; see PRD-GATE-008). Defaults finalized at v0.2b planning. |
| `[export]` | v0.4 | `markdown_root`, `layout`, `banner` | Controls `fid export` behavior. |

Compatibility policy: additive sections only. No removal without a
migration path.

### 2.3 `gates.toml` (v0.2b — draft shape)

Registered gate definitions live in their own committed file so registry
diffs are reviewable in isolation. Draft shape, finalized at v0.2b planning:

```toml
# Each gate is a versioned, executable definition. fid executes ONLY what is
# registered here (TRD-SEC-005). No shell strings: argv is an array.
[[gate]]
id = "go-test-race"
version = 1
argv = ["go", "test", "-race", "./..."]
cwd = "."
timeout_seconds = 600
env_allowlist = ["HOME", "PATH", "GOCACHE", "GOMODCACHE"]

[[gate]]
id = "golangci-lint"
version = 1
argv = ["golangci-lint", "run", "./..."]
cwd = "."
timeout_seconds = 300
env_allowlist = ["HOME", "PATH", "GOCACHE", "GOLANGCI_LINT_CACHE"]
```

Rules: bumping a definition's behavior bumps `version`; old receipts remain
valid because they snapshot the fields they ran with. Obligations reference
`id` (optionally pinning `version`). Removing a definition needs a
deprecation note; unknown IDs at `fid gate run` are hard errors.

### 2.2 Maintenance Grace Behavior

- Existing configs without `[maintenance]` or its key read as 300 seconds and
  are not rewritten merely by being read.
- Zero is valid and makes started-without-claim warnings immediate.
- Negative or malformed values are configuration errors; fid does not silently
  clamp or guess.
- Grace age is measured from the latest append-ordered `status_changed`
  activity row. `issues.created_at` is the fallback when no transition exists;
  non-status updates do not reset the window.

## 3. `pricing.toml`

Model pricing data used to compute `agent_runs.cost_usd` at run
close. Ships with defaults for current Anthropic/OpenAI/Google models;
user-overridable. The built-in set spans all three providers, and
`fid init` emits decimal prices with exact round-trip-safe precision so
fractional-dollar list prices survive `ReadPricingConfig` unchanged.

```toml
# Each model entry maps to (in_per_mtok, out_per_mtok) in USD.
# cost_usd = (tokens_in * in_per_mtok + tokens_out * out_per_mtok) / 1e6

[models.claude-opus-4-7]
in_per_mtok = 15.0
out_per_mtok = 75.0

[models.claude-sonnet-4-6]
in_per_mtok = 3.0
out_per_mtok = 15.0

[models.claude-haiku-4-5]
in_per_mtok = 0.80
out_per_mtok = 4.0

[models.gpt-5.4-mini]
in_per_mtok = 0.375
out_per_mtok = 2.25

[models.gpt-5.4-nano]
in_per_mtok = 0.10
out_per_mtok = 0.625

[models.gemini-2.5-flash]
in_per_mtok = 0.30
out_per_mtok = 2.50

[models.gemini-2.5-flash-lite]
in_per_mtok = 0.10
out_per_mtok = 0.40

# Add custom models as needed:
# [models.my-custom-model]
# in_per_mtok = 5.0
# out_per_mtok = 25.0
```

### 3.1 Pricing Behavior

- Pricing is **snapshot** on each `agent_runs` row at run end. This
  preserves audit trail across price changes.
- `fid init` emits numeric prices with enough decimal precision to
  round-trip every shipped default entry through `ReadPricingConfig`
  without losing fractional-dollar precision.
- If a model is missing from `pricing.toml` at run close, `cost_usd`
  is left NULL and a warning is logged. No silent guessing.
- Users can add or override any model entry.

## 4. `fid init` Behavior

`fid init` performs:

1. Creates `.fid/` directory.
2. Creates `.fid/.gitignore` containing `fid.sqlite`.
3. Creates `.fid/config.toml` with `[project] prefix = <PREFIX>`
   (default: project directory name, uppercased).
4. Creates `.fid/pricing.toml` with default model pricing.
5. Creates `.fid/journal/` directory.
6. Creates `.fid/fid.sqlite` with the current schema applied via
   migrations.
7. Appends the initial `project.initialized` journal event to the current UTC
   `journal/YYYY-MM-DD.jsonl` file.
8. Projects that event into SQLite, seeding the `roles` table with the default
   profile role list and writing the initial `projection_meta` row.

`config.toml` and `pricing.toml` are canonical committed configuration files.
They are not reconstructed by `fid rebuild`; the rebuild path reconstructs only
the SQLite projection from the journal plus the current schema.
